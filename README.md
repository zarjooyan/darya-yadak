# دریا پارت | Darya Part

فروشگاه نمایشی لوازم یدکی خودرو با **Next.js App Router، React، TypeScript و Tailwind CSS v4**. رابط کاربری فارسی و راست‌چین است و از Design System روشن/تیره مبتنی بر آبی، سرمه‌ای و خاکستری استفاده می‌کند.

## شروع توسعه

```bash
npm install
npm run dev
```

سایت در `http://localhost:3000` و پنل مدیریت در `http://localhost:3000/admin/` اجرا می‌شود. دستور `npm run dev` هم‌زمان Next.js و سرویس محلی پنل را اجرا می‌کند.

در اولین ورود، یک رمز عبور حداقل ۸ کاراکتری برای مدیر تعیین کن. رمز به‌صورت hash شده و کلید نشست در فایل محلی `.admin-auth.json` ذخیره می‌شود؛ این فایل وارد Git نمی‌شود. نشست با Cookie امن HttpOnly و اعتبار ۸ ساعته مدیریت می‌شود. برای بازنشانی رمز، سرور را متوقف کن و فایل `.admin-auth.json` را حذف کن.

سرویس محلی فقط روی `127.0.0.1:3031` گوش می‌دهد. اطلاعات محصولات مستقیماً در `src/data/products.json` و تصاویر در `public/uploads/products/` ذخیره می‌شوند.

## Build و انتشار

```bash
npm run build
```

Next.js با `output: "export"` فایل‌های استاتیک را در پوشه `out/` می‌سازد. هر push به شاخه `main`، workflow گیت‌هاب اکشنز را برای build و انتشار روی GitHub Pages اجرا می‌کند.

آدرس هدف: https://zarjooyan.github.io/darya-yadak/

اگر GitHub Pages قبلاً فعال نشده باشد، در مخزن به Settings → Pages بروید و Build and deployment → Source را روی **GitHub Actions** بگذارید.

## امکانات فعلی

- صفحه اصلی واکنش‌گرا، جستجوی نمونه و انتخاب خودرو
- دسته‌بندی‌ها و صفحات استاتیک محصولات با URL خوانا
- پنل مدیریت محلی با نقش Admin
- مدیریت دسته‌بندی‌ها، برندها و فهرست خودروهای پیشنهادی
- ذخیره مستقیم محصولات و آپلود تصاویر روی فایل‌های پروژه
- عنوان و توضیحات متای قابل تنظیم برای هر محصول، canonical، Open Graph و metadata زبان فارسی
- Schema برای Organization، WebSite/SearchAction، Product، CollectionPage و FAQ
- تولید sitemap و robots.txt
- Web App Manifest با حالت نصب مستقل، آیکون‌های SVG و پشتیبانی از مسیر GitHub Pages\n- انتشار خودکار روی GitHub Pages

## نکات مهم

GitHub Pages فقط خروجی استاتیک را میزبانی می‌کند؛ سرویس محلی مدیریت و احراز هویت فقط روی سیستم توسعه اجرا می‌شوند و در خروجی عمومی قرار نمی‌گیرند. برای قابلیت‌های سروری در محیط production به میزبان دارای runtime سرور نیاز است.

برای سئوی واقعی نیز پس از اتصال دامنه نهایی، آدرس canonical و sitemap را با همان دامنه تنظیم کنید، سایت را در Google Search Console ثبت کنید و داده‌های ساختاریافته را با اطلاعات واقعی و مطابق محتوای قابل مشاهده نگه دارید.


## تست محلی Web Push

سیستم Push اختصاصی پروژه برای تست محلی آماده است و از OneSignal یا Firebase استفاده نمی‌کند.

1. وابستگی‌ها را نصب و سرویس‌ها را اجرا کنید:
   `npm install`
   `npm run dev`
2. سایت را در مرورگر روی `http://localhost:3000` باز کنید.
3. در پایین سایت، «فعال‌سازی اعلان» را بزنید و مجوز مرورگر را تأیید کنید.
4. وارد `http://localhost:3000/admin/` شوید و پس از ورود، «مدیریت اعلان‌ها» را باز کنید.
5. عنوان و متن اعلان را وارد و آن را ارسال کنید. برای تست دریافت، می‌توانید از یک مرورگر یا پروفایل دوم هم اشتراک بگیرید.

کلیدهای VAPID و اشتراک مرورگرها به‌صورت محلی در فایل‌های `.push-vapid.json` و `.push-subscriptions.json` ذخیره می‌شوند و در Git قرار نمی‌گیرند. این فایل‌ها را حذف نکنید؛ حذف کلید VAPID باعث نامعتبر شدن اشتراک‌های قبلی می‌شود.

توجه: برای تحویل واقعی Push، مرورگر باید به Push Service خودش دسترسی اینترنتی داشته باشد. تست از طریق `localhost` انجام می‌شود؛ GitHub Pages در این مرحله نقشی در ارسال اعلان ندارد.
